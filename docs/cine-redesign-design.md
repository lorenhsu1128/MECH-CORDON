## 二、絕區零的過場語言（觀察）

### 1. 三種格式，各有分工（官方 ZTALK）

| 格式               | 用途                           | 官方的說法                             |
| ------------------ | ------------------------------ | -------------------------------------- |
| 固定插畫（一枚繪） | 情緒與氣氛                     | 比完整動畫更有力                       |
| 動態漫畫           | 大部分的劇情                   | 玩家照自己的節奏看，短時間交代很多內容 |
| 3D 過場            | 激烈戰鬥、重大轉折、情緒最高點 | 只在這些時候用                         |

- **沒有一種格式什麼都做得好**，所以三種要接起來用。例如 2.1 版逃出下水道那一段：固定插畫定下氣氛 → 動態漫畫控制節奏 → 3D 過場接動作與緊張感。
- **顏色與光線是說故事的工具**：憤怒的回憶用火紅加破碎的紋理，憂鬱的角色用單色。
- 動作戲用鏡頭橫移與越軸表示緊張與轉折；情緒戲先累積、再釋放。
- 動畫師自己演一次、錄參考影片，再照它做表情、手勢、時機。
- 對話全部有配音；評論說漫畫格不但不妨礙喜劇的時機，反而更好掌握。

### 2. 動態漫畫與對話場景（主線合集）

開頭 25 分鐘的順序：3D 過場（家裡的電視新聞）→ 動態漫畫（搶劫、閃光彈、追逐）→ 3D 過場（墜入空洞）→ 玩的部分 → 對話場景 → 漫畫 → 3D 過場（怪物化）→ 漫畫（新聞）→ 對話場景。**幾分鐘就換一種格式。**

**動態漫畫**

- 畫面外框是一條**底片**（上下有孔、左右有「LT 上一頁／RT 下一頁」），**玩家按鍵翻頁**。
- 每一頁是一格大圖，或二到三格的**斜切分格**。
  - 格子是完整上色的插畫，構圖很戲劇：低角度、極近的臉、手裡的槍。
  - 鏡頭在格子裡慢慢推、移，人物稍微動。
- **對話框是黑底白字的方框**，帶尖角指向說話的人，一格放一到三個。旁白也是方框。
- **狀聲詞與符號**：
  - 「CLICK」「POW!」的大字。
  - 「!」放在爆炸框裡、「?」、汗滴與怒氣符號。
- 一頁裡常常是「同一個場面的兩個瞬間」：先是全景，下一格是表情特寫。
- **格子大多是靜止的**（每秒兩格抽出來看，15 秒內人物幾乎不動）。
  - 動的是新的格子：從旁邊滑進來，疊在同一頁。
  - 格子裡的特效會動：旋風變大、子彈飛過、狀聲詞跳出。
  - 對話框一句一句出現。
  - 這是「保持＋少量特效」的有限動畫，素材很省。

**對話場景**

- 3D 角色**半身**站在畫面中，背景是當下的 3D 場景（景深很淺、模糊）。下方是半透明黑色對話框，名字在框頂。
- 第二、第三個人加入時，**畫面用斜線切成兩格或三格，各放一個人**（主角也在裡面），背景各自延續。
- 說話的人有表情與手勢（托腮、抱胸、比手指、閉眼笑），沒說話的人也會小動作。
- 選項是黃色膠囊，跳在畫面中央。
- **這種對話場景是主線分量最多的格式**，比漫畫更多。

**轉場**

- 漫畫 → 3D 之間用資料毀損的故障、黑畫面。
- 3D 過場結束直接接玩的部分（同一個場景）。

### 3. 3D 即時演算的日常短劇（艾蓮 角色預告）

- 真的在「演戲」，幾乎不打鬥。
  - 被窩裡探頭，走廊的同學、置物櫃前的對話。
  - 咖啡廳的老客人、蛋包飯上的番茄醬字。
- 對話用**正反打**（兩個人輪流的過肩鏡頭）。表情的小動作很多：咬棒棒糖、托腮、閉眼。
- 大量**物件與局部特寫**：盤子、對講機、高跟鞋的腳步、窗外的街景。
- 結尾突然切換氣氛：
  - 畫面變成**黑白反轉、線稿**，墨水般的斬擊。
  - 接紅色的角色登場，最後落在 LOGO。

### 4. 角色展示片（艾蓮 角色展示）

- **平面設計的色塊**是主角：
  - 洋紅、橘、青、黃的大圓、三角、波浪線、「＋」點陣。
  - 角色變成**單色剪影**疊在色塊上，3D 畫面也常整個換成灰階＋一個單色。
- **大字**：「RUN」「INTRODUCING」這種巨大斜體字壓在人物前後，人物從字裡穿出來。
- **手機通知**「NEW MESSAGE!」跳出、圓形的角色徽章。
- **卡點**：每一拍換一種配色或構圖。
- 戰鬥的段落用：
  - 低角度的 3D 動作。
  - 刀光一閃就換色、閃白。
  - 十字星光、鋸齒狀的爆光（漫畫的效果框）。

### 5. 2D 手繪短片（珍・杜〈驚魂之夜〉）

- **雙色調**：整個畫面只用二到三個顏色（螢光綠＋紫、洋紅＋藍、黃＋紅），換段落就換一組。
- **極端的特寫**：眼睛塞滿整個畫面、咬牙的嘴。
- **斜切分割**：兩個角色在一個畫面裡用斜線切開；碎玻璃般的多格同時出現好幾張臉。
- **剪影與光束**：手電筒的光柱、白色剪影的動作、背景的速度線。
- 動作的瞬間：
  - 角色化成野獸般的大型剪影。
  - 一刀劈開畫面，碎片四散。

### 6. 預告片（PlayStation 預告）

- **動態字**：巨大的斜體字從畫面掃過（「NEW」「COOL」），字裡透出畫面。
- **資料毀損的故障**：色塊錯位、畫面拉扯，用在換鏡。
- **衝擊畫格**：
  - 畫面反白成線稿（白底紅線、白底藍線），一兩格就切回來。
  - X 形與十字形的星光、爆光。
- 節奏：越剪越快，最後用閃白收尾。

### 7. 官方過場團隊怎麼做（ZTALK 字幕全文）

- **三種格式的理由**：
  - 漫畫讓玩家照自己的節奏點著看，時空比較自由，資訊密度高。
  - 固定插畫突顯情緒。
  - 3D 用在大量特效的激烈戰鬥與大轉折。
  - 很長的對話玩家坐不住，在情緒衝上來的地方插一張固定插畫，讓情緒有出口，同時把很多對話放在這張圖上當過渡。
- **漫畫的場景比概念圖樸素**：漫畫格的場景只為劇情與氣氛服務，不做搶眼的設計。
- **顏色**：
  - 單色、雙色、多色各有效果。
  - 沉重、悲傷的戲用單色控制整個畫面（雨果的那張）。
  - 復仇用燒不熄的火色加破碎的形狀（伊索德）。
- **分鏡的四個目標**：順暢、刺激、感人、留下印象。
  - 多人的戲先排好每個人的位置與走位，再決定鏡頭、焦距、構圖。
  - 用軸線安排優勢與劣勢的位置：角色在左邊佔上風，另一股勢力從左邊冒出來就變成劣勢。
  - 轉折之前，鏡頭慢慢越過軸線去拍到關鍵的東西（旗子），讓觀眾隱約感到要翻盤了。
- **催淚的公式**：先長時間鋪陳情緒，在最高點放一個觸發事件。
  - 例：小希德以為老希德要醒來了（手指動了一下），下一秒他倒下不再回應，眼淚在這時流下。
- **登場**：先出現角色最有代表性的東西，再出現本人。例：先是青冥鳥，然後手與符咒，最後才是儀玄。
  - 一打多：鏡頭只對準主角，主角在畫面中央保持從容，敵人不斷進出畫面。
- **節奏的鬆緊**：
  - 很緊張的一段之後，用一個好笑的小動作收尾（鈴喝水），後來變成迷因。
  - 過場裡也會放簡短的按鍵互動，節奏比一般過場快很多，接起來不能和戰鬥脫節。
- **表演**：動畫師自己演、錄參考影片。表情、嘴型與身體分開錄，再合起來。
  - 眼睛是表演的主要部分（瞳孔放大）。
  - 依角色個性調說話的方式（可愛的角色嘴型更有彈性）。
- **協作**：配樂與音效依過場的情緒與結構一起安排，音效有時也負責敘事。

### 8. 要避開的問題（New Frame Plus 的分析）

動畫師 Dan Lowe 認為絕區零的戰鬥動畫非常好，但對話與過場有「動作過度」的問題：

- **待機時軀幹也在飄**：維持姿勢時整個身體輕輕浮動，看起來像泡在浪池裡、沒有重量。頭髮衣服可以動，重心不該飄。
- **物理太多**：每一撮頭髮、每一片衣角都在晃，變成一直存在的雜訊，干擾視線。
- **表演的陳腔濫調**：一句平常的話也配誇張的大動作、連續擺好幾個可愛姿勢，「比劃情緒」而不是「感受到情緒」。
  - 每一句都用最大的能量，看久了很累，也不真誠。
- **對話場景和過場像兩個遊戲**：對話場景的姿勢與表情很保守，到了過場突然變得很誇張，20 秒後又變回去，像換了一個人。
- **角色之間的差異被抹平**：大家在過場都用類似的誇張方式動，個性的對比反而變小。
- **好的動畫會引導視線**，要動的地方動，該靜的地方靜。

**我們的做法**：

- 對話分格與漫畫、3D 用同一套「角色個性表」，同一個角色在哪裡都是同樣的動法。
- 待機只動頭、頭髮與眨眼，身體不飄。
- 姿勢只在台詞需要時換，平常的句子不換姿勢。

## 三、現況

- **過場**：第 1 周目約 26 段、共約 19 分鐘（序章 2 分 12 秒、各章開場 36～72 秒、章末 23～50 秒、抉擇 10～23 秒），字幕台詞約 160 句。
- **演員**：全部是 3D：
  - 機甲、Boss、地圖。
  - 低面數的寫實人物（委託方的臉蓋在剪影裡）。
- **角色**：只出現在「通訊分割」的小窗。
- **語音**：過場的台詞有語音的只有約 42 句，大多是字幕＋無線電音效。
- **已經有的素材**：
  - 立繪：10 個角色有完整的立繪（表情、眨眼、對口型；ECHO 有分層的頭髮與頭部晃動）。宿敵 16 位還沒做（立繪第 5 期）。
  - 語音：每個角色都有語音（VoxCPM2，中文＋日文），新台詞照現有的流程產生就好。
  - 角色產生器：ComfyUI（NoobAI＋Qwen-Image-Edit），可以產生新的插畫。
  - 絕區零的介面已有漫畫分鏡背景（C3）、擊破大字定格（C4）、文字動畫的「街頭」模板。
  - 渲染風格已有漫畫衝擊畫格 `comicHit`。

**限制**：

- 遊戲裡沒有動漫風的 3D 角色模型，現有的人物 GLB 是低面數的寫實人。做 3D 的動漫角色（建模、骨架、表情）是另一個大工程。
- 所以「角色演出」實際上靠：
  - 2D 的立繪與新產生的插畫。
  - 3D 的機甲（機甲本身就是角色的身體）。

### 立繪與語音重新產生（2026-11-12 使用者：都可以重新產生）

現在的立繪是為通訊框與劇情畫面設計的（每人 2 個姿勢、正面）。過場要演戲，所以照過場的需要重新訂規格，不遷就現有素材。

**立繪 v2（演技表）**

- **姿勢 8～12 個，依角色個性挑**。例如：
  - 霍斯特：抱胸、拍桌、指人、轉身背對。
  - 薩奇：推眼鏡、看平板、抱臂沉思。
  - 芮恩：握拳、縮肩、敬禮。
- **角度**：正面、左右各 3/4 側。對話分格可以讓兩個人**面對面**（正反打），不必都看鏡頭。
- **景別**：
  - 半身是主力（對話分格）。
  - 全身與特寫給漫畫和固定插畫用。
- **表情**：14 個左右，照舊有眨眼與三種嘴型。
- **分層**：全部角色都拆成後髮／身體／頭／前髮。
- 每個角色另做一張「**角色個性表**」，決定怎麼動：
  - 輕或重、快或慢、吵或靜。
  - 待機的幅度、換姿勢的頻率、慣用的手勢。
- 換姿勢用動畫的「保持＋兩格過渡」（中間插一張動態模糊的過渡格），不做補間的滑動。
- 宿敵 16 位直接用新規格做（取代原本的立繪第 5 期）。

**語音 v2（照表情配情緒）**

- 每句台詞已經有表情（`data/line-expr.js`），新的語音照表情決定**語氣**：平靜、激動、低語、喊叫、悲傷……
- **候選模型**：
  - 現在的 VoxCPM2（可以控制風格的聲音克隆）。
  - IndexTTS2（B 站開源，AAAI-26）：聲音與情緒可以分開給參考音檔或文字描述，還能**指定每句的長度**，可以對齊配樂的節拍與漫畫翻頁。
- **做法**：
  - 每個角色準備幾種情緒的參考音。
  - 做一個試聽頁（像以前的 ECHO 語音試聽），同一句用不同模型與情緒並排，讓使用者挑。
  - 中文與日文都要。
- 2026-11-06 的台灣腔試驗已經否決，不再重跑那個方向。

**主角**：如果決定露臉，主角也用同一套規格做。

## 四、方案

每個方案都包含：

- **全語音**：所有台詞都有角色的中文／日文語音，旁白也配音。
- **對口型與表情**：照台詞的表情與動作（`data/line-expr.js` 的那一套）。
- **照舊的部分**：可以略過、有文字畫面的備案、列在過場劇場裡。

### A. 動態漫畫（絕區零主線的做法）

- **格式**：每一段過場是幾頁漫畫。
  - 斜切的分格依序落下、蓋章。
  - 鏡頭在格與格之間平移、推近，格子裡的東西會動。
- **格子裡放什麼**：
  - **角色的插畫**：用角色產生器以立繪為參考產生，畫成和那句台詞相符的動作與表情。
  - **3D 即時畫面**：機甲、Boss、爆炸在格子裡即時算繪，套漫畫的描線與網點。
  - **立繪**：會眨眼、對口型。
- **對話**：氣泡跟著說話的人，語音播完換下一句。狀聲詞的大字（轟、ZAP）配音效跳出來。
- **角色演出**：
  - 每一格是一個表演的瞬間（抱胸、拍桌、回頭）。
  - 同一格裡用分層做小動作：頭髮、呼吸、眨眼、說話。
- **適合**：委託方之間的爾虞我詐、ECHO 和主角的對話、章末的後果。
- **素材量**：每段約 8～15 張插畫，全部約 250 張。
- **優點**：最像絕區零；台詞再多也不拖；插畫可以畫出 3D 做不到的表情。
- **缺點**：
  - 插畫要逐張挑。
  - 多人同框的一致性要靠合成（角色各自產生、去背，再疊在背景上）。
  - 戰鬥的爽快感比 3D 弱。

### B. 三段式混合（照官方的分工，建議）

依照每一場戲要做的事挑格式，同一段過場裡接著用：

1. **固定插畫**開場：一張大圖定下氣氛，慢慢推近；ECHO 或委託方的旁白。
2. **動態漫畫**交代事件：方案 A 的做法。
3. **對話分格**交代人物之間的對話：方案 C 的做法。
4. **3D 機甲動作**當高潮：沿用現在的 3D 過場引擎，加上：
   - **駕駛艙的角色插入**：畫面切一半，宿敵或僚機的立繪在駕駛座上喊話，對口型。
   - **衝擊畫格**：反白線稿、十字星光、斜切的大字。
   - **斬擊換色**、黑白＋單色的定格。

- **角色演出**：插畫與立繪負責表情，機甲負責動作。
- **素材量**：每段約 4～10 張插畫＋ 1～3 個 3D 鏡頭段落，全部約 180 張。
- **優點**：
  - 情緒、劇情、動作各用最擅長的格式。
  - 現有的 3D 過場（地圖、機甲、Boss 的運鏡）大部分可以改造再用，不用丟。
- **缺點**：要做的新東西最多：漫畫舞台、插畫流程、插入畫面都要做。

### C. 對話分格（絕區零的對話場景）

- **格式**：照絕區零主線分量最多的那種對話場景，只是 3D 角色換成我們的分層立繪。
  - 背景是即時的 3D 場景：作戰室、駕駛艙、戰場，機甲在後面動，淺景深。
  - 一個人時半身站在畫面中；兩三個人時畫面斜切成兩三格，各放一個人。
  - 下方是對話框，名字在框頂。
- **鏡頭**：
  - 每格各自慢慢推近、輕微晃動。
  - 分層的頭髮、頭、身體有一點視差。
  - 換說話的人時那一格往前、其他格變暗。
- **角色演出**：
  - 說話的人用照台詞的表情、動作、對口型，姿勢照台詞換（p1／p2／p3）。
  - 沒說話的人眨眼、呼吸。
- **素材**：不用插畫，用立繪 v2（每人 8～12 個姿勢、正面與 3/4 側，見上一節），兩個人可以面對面輪流說話。
- **優點**：
  - 最快、最省，和絕區零的對話場景最像。
  - 也可以拿來做作戰室與簡報裡的對話。
- **缺點**：
  - 人物只能做演技表裡有的姿勢，不能走路、打鬥。
  - 一直用會像視覺小說，要和漫畫、3D 交替。

### D. PV／MV 式（角色展示片的平面設計）

- **格式**：配樂卡點的剪輯。
  - 平面色塊（大圓、三角、波浪、點陣）。
  - 角色的單色剪影與大字。
  - 3D 畫面換成灰階＋單色。
  - 衝擊畫格、資料毀損的故障。
- **角色演出**：
  - 立繪的表情在色塊上跳出、剪影的動作。
  - 「NEW MESSAGE!」式的通訊插入。
  - 宿敵的名牌大字。
- **素材**：用現有立繪與 3D，不太需要新插畫；配樂要選節奏明確的曲子。
- **適合**：序章、章節開場、宿敵登場、周目的開頭。
- **不適合**：長對話、悲傷的戲。
- **優點**：最有絕區零 PV 的味道，素材少、做出來效果強。
- **缺點**：整個主線都用它會很吵、很累。

### E. 2D 短片風（雙色調的有限動畫）

- **格式**：只用二到三色的雙色調插畫（Qwen 改圖＋程式的色調映射），以少量影格配合程式的變形做「有限動畫」。
  - 極端特寫、斜切分割、碎玻璃格。
  - 光束、剪影、整個畫面換色。
- **角色演出**：每個動作 2～4 張影格。動作的時機用配樂卡點，表情用特寫的影格。
- **適合**：ECHO 的記憶片段、真結局、第 3 周目的私人頻道這些情緒最高點。
- **優點**：最有作者感、最強烈。
- **缺點**：
  - AI 產生連續影格很難一致，大量做的品質不穩。
  - 只建議用在少數幾段。

## 六、共用的技術（不管選哪個方案）

1. **過場的 2D 舞台**：在過場引擎加 2D 層，和 3D 畫面一起排時間軸。
   - 分格、插畫圖層、立繪演員、氣泡、狀聲詞、大字、色塊。
   - 劇本格式加 `panels`／`art`／`actor2d` 之類的鏡頭種類，3D 鏡頭照舊。
2. **3D 畫面進格子**：3D 場景算繪到 RenderTarget，放進漫畫格（第 5 章電視牆的合成已經這樣做），套描線、網點、雙色調。
3. **場景插畫的產生流程**：角色產生器多一個「場景插畫」分頁：
   - 以角色的主圖為參考，Qwen-Image-Edit 改成指定的動作、表情、構圖。
   - BiRefNet 去背、See-through 拆層。
   - 背景另外產生，多人的格子合成。
   - 插畫存 WebP，依章節打包成 `dist/lib/cine-art-<章>.js`，第一次播那一章才載入。全部約 20～30 MB。
4. **語音**：
   - 新台詞加進 `scripts/voice-lines.js` 的收集，照現有流程產生中文與日文語音（`voice-gen.py`，每句 2 次挑最像的）。
   - 旁白另外選一個聲音。
   - 字幕跟著設定的語言。
5. **卡點**：配樂的拍點表（每首曲子量一次 BPM 與起點），劇本可以寫「第幾拍」。
6. **主角怎麼呈現**：主角是玩家，現在從來不露臉。要決定（見下方）。

**這次學到的（換台電腦也適用）**

- ComfyUI 做表情時記憶體大約 15～24 GB（Qwen 與 SDXL 兩個模型），會隨模型切換上下；`/free`（`{"unload_models":true,"free_memory":true}`）可以卸下模型，比整個重啟快。Windows 的 `FreePhysicalMemory` 不算待命快取，看可用記憶體要用 `\Memory\Available MBytes`。
- Claude Code 在記憶體緊時會停掉它的背景工作連同整個程序樹；ComfyUI 若是從那裡面開的會一起被停，批次腳本又沒檢查就會把剩下的全部當成失敗跑過去。批次要檢查 ComfyUI 還在、失敗重試、連續失敗就停。
- 等待其他程序結束不要用「命令列含某字串」比對（查詢自己的命令列也含那個字串，會永遠等）；停程序時同樣會比對到下指令的 shell 自己——比對字串寫在 .ps1 檔裡再執行。從 node 的 `execFileSync` 呼叫會開 ComfyUI 的腳本時，輸出不能接管線（新開的 ComfyUI 會繼承管線，`execFileSync` 一直等到 ComfyUI 關掉）。
- 數新圖時不要 `find` 整個 `tools/comfyui/runtime`（含模型，一次 5 分多）。
- 輔助腳本在 `tools/portrait-v2/`（README 有說明；腳本裡的路徑是原本那台電腦的暫存資料夾，要改）。
