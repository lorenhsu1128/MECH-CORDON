# 渲染風格「絕區零」

2026-11-11 使用者要新增一個像《絕區零》（HoYoverse，2024）的渲染風格：**和遊戲畫面仔細比對，整個遊戲的渲染、光影、地圖物件、敵人的配色都可以調整，要一樣的感覺；每一種視角在不同地圖的遊玩畫面都要檢查**。在分支 `zzz-style` 開發。

## 一、定案（2026-11-11）

1. **角色與場景分開渲染**（可以）：機甲、敵人＝兩階賽璐璐＋物體色的細描線＋細的邊緣光；場景＝柔和的著色、不描線、不做色階。
2. **敵人的配色**：用絕區零的色系與色溫，**不是全部同一套配色**——各種敵人保留自己的色相，換進「白殼／深色身體／霓虹發光」的系統。玩家與友軍保留自己選的配色。
3. **時間與天空一起改**（黃昏的金橘、晴天的淺藍、手繪感的積雲）。
4. **特效一起做**：高飽和的發光斬擊與命中、打出失衡與擊破時的漫畫網點衝擊畫格。
5. **參考圖放進版本庫**（`tools/style-refs/`，README 記來源），並從影音網站多蒐集遊戲畫面。

## 二、參考資料與比對的結論

參考圖 37 張（`tools/style-refs/`）：維基的場景與敵人截圖、YouTube 無解說實況抽出的戰鬥與探索畫格、官方活動插圖。

**畫面的特徵**（看圖整理）：
- **兩套渲染**：角色是賽璐璐（明暗交界銳利、細的深色描線是物體色的暗版、向光的輪廓有細亮線）；場景是柔和的半寫實（像烘焙過的全域光照、乾淨的平塗貼圖、細節少、沒有描線）。
- **光影**：太陽強、投影長而清楚；陰影偏冷的藍灰（或青綠），亮面偏暖；暗部被拉亮、對比低；大氣透視重（遠景淡成天空色）；空洞裡是灰色的以太霧。
- **配色**：場景以水泥灰、米色、灰藍為主，少量高飽和的強調色（橘紅鋼樑、黃黑警示條紋、招牌）；但整體**不是很灰**（量到的飽和度比我們原本的畫面高）。
- **敵人**：以骸＝白色骨頭／陶瓷的硬殼＋深藍或黑的身體＋發光的核心與裂紋（霓虹藍、螢光綠、紫、紅）；機械類＝黑白配色＋青色燈。
- **特效**：斬擊、命中是高飽和加色的橘、粉、洋紅、青；連攜與大招有衝擊畫格（反色、故障、網點）。

## 三、做法

### 著色器（`render/style/shader.js`；全部是 uniform，不增加著色器的變體）
- **角色／場景分開**（`split`）：`stTn()`＝這個材質用不用色階（機體類 `stCat`＝1 才用）；場景走原本的物理渲染。
- **陰影的冷色**（`shTint`／`shTintK`）：間接光（半球光、環境貼圖）乘上冷色，照不到太陽的地方變成藍灰色。
- **場景的配色**（`envK`、`envSat`、`envAccent`、`envAccTh`、`envComp`、`envLift`）：一般顏色與強調色（飽和度超過門檻）分開調飽和度、明度壓縮、暗部抬升。
- **地形平滑**（`envSmooth`）：地形網格另外存平滑的法線與平滑的頂點色（`world.js` 的 `stCol2`，每個頂點取周圍面的平均），打開時不用每個面的法線與顏色（其他風格照舊是多邊形的面）。地形材質以 `markSmoothable` 標記。
- **敵人的配色**（`foeK`、`foeHi`、`foeLo`、`foeHue`、`foeGlow`）：MechEntity 生成時 `team === 'enemy'` 的模型以 `tagTeam` 標記材質（`stTeam`）；亮度決定白殼與深色身體之間的位置、保留原本色相的比例（不同敵人不同色）、高飽和的部分變霓虹色、發光加強。
- **螢幕空間的邊緣光**（`srim`、`srimW`、`srimColor`，`render/style/pipeline.js` 的合成）：機體類的像素往太陽在畫面上的方向偏移幾個像素，深度是遠處（背景）＝向光的輪廓，加一條亮線。
- **敵人配色看材質本身的顏色**：白殼或身體由材質色×頂點色（不含貼圖）決定，貼圖的明暗再乘回去（直接看每個像素時，GLB 灰階貼圖的細節會被推成黑白的斑塊）。
- **地形平滑不改原本的法線**：平滑的法線放在另一個屬性 `stNrm2`（SSAO 的法線材質讀 `normal`，改了會讓其他風格的地形 AO 也變），平滑的顏色 `stCol2`；材質的程式快取鍵多一個 `s`。

### 天空（`render/style/atmos.js`）
- `skyGlow`／`skySun`：太陽周圍的大範圍暖光與光暈；雲的亮面染成陽光色、暗面 `skyShade`；`cloudSize`＝雲的大小（絕區零的積雲比較大塊）。

### 特效
- **刀光**（`slash`，`entities/mech-trails.js`）：顏色加飽和、提亮（色相不變）、留得更久。
- **漫畫的衝擊畫格**（`comic`、`comicInk`、`comicPaper`，`pipeline.js` 的調色）：打出失衡（`fbBreak`、客機的 `fbEvent`）、擊破大型敵人（`fbKillLocal` 的 big）、自己完美迴避（`pqbFx`）時 `Game.comicHit(k)`（`game/juice.js`）：0.05 秒反色 → 紙色為主＋暗處的 45° 網點＋放射狀的速度線 → 0.3 秒內淡出；用實際經過的時間、0.5 秒內不重複；`ctx.comicPush()`＝`comicState()`。只有 `comic` 大於 0 的風格看得到，各端自己顯示（不同步）。

### 依地圖的覆寫（`byTheme`）
內建風格可以多一個 `byTheme: { 主題 id | '@roof'（地下） | '@night'（夜間變體，主題的 noTod）: { 參數 } }`（`builtinParams` 帶在 `P._byTheme`），`Game.styleThemed(P)`（`game/render-setup.js`）依目前的主題、地下、夜間依序蓋上去（`renderMain`、水面）。不能放色調映射與陰影種類（要重新編譯）。絕區零：模擬訓練場＝絕區零的 VR 訓練室（青綠色的空間）、火山與方舟＝紅色的夕陽與暖色的陰影、軌道＝高空、雪地提亮、地下與暗的地圖改暖的陰影、夜間＝月光的藍。

### 比對工具（`scripts/style-shots.js`）
每張地圖出擊一次（固定亂數；`--maps=dunes:night` 指定變體），鏡頭方向固定在太陽的側面（`--sunrel`），敵人擺到玩家前方、AI 停住、清掉子彈與特效，依序拍俯視／追尾／第一人稱 × 每個風格；`--p=鍵:值,…` 不必重新建置就能試參數（只套在第二個以後的風格）。`--lineup=類型,…` 把這些敵人排成兩排（看敵人的配色）、`--hud=0` 藏起 HUD、`--extra=garage,hub` 拍機甲庫與作戰室、`--comic` 拍衝擊畫格的兩拍。輸出 `test-results/style-shots/<tag>/` 與並排的 `index.html`（含參考圖與統計）。效能：`node scripts/perf-probe.js --style=zzz --compare=<基準>`。

## 五、實作紀錄

- **2026-11-11**：第 1～5 期。調參數的過程（全部地圖 × 追尾＋俯視的平均，參考圖 26 張＝亮度 0.40、標準差 0.13、飽和度 0.29、暗部 0.26 偏冷、亮部 0.58 偏暖）：
  - 第一版（ACES、曝光 0.82、霧色混入 0.45、場景降飽和 0.55）：亮度 0.80、飽和度 0.12——太亮、太灰（絕區零沒有評論說的那麼灰）。
  - 線性色調映射、太陽 1.6／環境光 0.75、陰影冷色 0.85、場景飽和度 1.3、強調色 1.5：亮度 0.45、標準差 0.20、飽和度 0.25、暗部偏冷 −0.05。
  - 之後依地圖覆寫（暗的地圖藍色陰影會變深藍 → 改暖）、對比 0.95。
  - 效能（`perf-probe`，集散場 40 秒）：每格 CPU 中位數 4.9 → 5.8 ms、>50 ms 的格相同（都是載入第一格的預熱）。

  - 觀察：俯視時地圖本身（大片平地）比絕區零的街道空，機體與敵人的配色、陰影的冷暖、天空與衝擊畫格最像。
