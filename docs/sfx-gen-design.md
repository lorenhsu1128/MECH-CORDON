# 自製音效（AI 產生的素材＋分層＋程式合成）

2026-11-22 使用者：「我想自行產生適合遊戲的音效，目前是用別人的，聲音單調無聊」。調查與提案之後的定案：

1. **風格＝混合**：實彈武器、爆炸、機體的金屬與液壓偏寫實、厚重（機戰傭兵6、MechWarrior 5）；能量武器、推進器、QB、蓄力、介面偏動漫科幻（鋼彈的光束、誇張的推進器）。
2. **全部自己產生**：`src/assets/sfx/`、`src/assets/sfx2/` 的第三方素材全部換掉（換完拿掉 `CREDITS.txt` 的對應項目）。
3. **照分期的順序做**（下面第 4 節）。
4. **由 Claude 直接挑**：每個鍵依自動評分挑，使用者只抽聽、否決不好的（和立繪第 4 期之後一樣）。
5. **第 0 期兩個模型都試**，使用者試聽之後決定用哪個。

## 1. 現在為什麼單調（調查）

- 素材不是為機甲做的：現實槍械（Still North Media）、中世紀刀劍、鑄鐵鍋（`iron*`）、通用的科幻包；機甲的重量靠把音調壓低（`recipes.js` 的音高 0.55～0.78），聽起來悶而不厚。
- 同一個聲音用在很多地方：`SFX.play('charge')` 25 處、`heavy` 13 處、`laserBig` 12 處、`alarm` 10 處，58 種專屬敵人與 28 隻 Boss 的招式大多播這幾個，聽不出是誰。
- 變化少：197 個檔案約 2.6 MB，大多不到 1 秒；步槍的近距離 4 個、大部分武器 1～3 個素材。
- 聲音不帶資訊：敵人的閃避（推進器的預兆）、破綻、Boss 的蓄力與大招幾乎沒有專屬的聲音（動作遊戲很需要「用耳朵看」）。

## 2. 模型（2026-11 查核）

| 模型 | 授權 | 規格 | 結論 |
| --- | --- | --- | --- |
| MOSS-SoundEffect v2.0（OpenMOSS，2026-05） | Apache-2.0 | DiT＋流匹配、DAC VAE、Qwen3 文字編碼；1.3B；48 kHz；0～30 秒；中英文提示詞；可以微調 | 試 |

| MMAudio、HunyuanVideo-Foley | 權重不能商用或條款不清楚、主要是影片配音 | | 不用 |

兩者都沒有公開、可信的品質比較，所以第 0 期實際產生、讓使用者用耳朵選。

## 3. 做法

- **環境**：`npm run sfx:setup`（`scripts/sfx-setup.js`）把 MOSS 的原始碼（固定版本）、Python 3.12＋PyTorch 2.9 cu128 的環境、兩個模型與評分用的 CLAP 裝到 gitignore 的 `tools/sfxgen/`（`HF_HOME`＝`tools/sfxgen/hf`）。Windows 沒有 Triton，MOSS 一律 `TORCHDYNAMO_DISABLE=1`。產生音效時不和 ComfyUI、語音產生、完整測試同時跑（記憶體，見 memory-budget）。
- **AI 產生素材**：照 `audio/recipes.js` 的分層（near／far／body／mech／tail…）每一層各自產生，每個鍵 8～16 個候選。
- **自動評分與挑選**：提示詞與聲音的相似度（CLAP）、起音的利落度、長度、響度、雜音、削波；挑 4～8 個變化版本，修剪、淡出、統一響度、單聲道 mp3。
- **程式合成**：會跟著遊戲變的部分（伺服的音高跟著速度、蓄力跟著充能、推進器跟著推力）留給 `audio/synth.js`。
- **試聽**：標題「工具與其他」的試聽頁（和配樂產生器同一種用法：舊版與候選並排、在遊戲情境裡試播、換成這個）。

## 4. 分期

| 期 | 內容 |
| --- | --- |
| 0 試做 | 兩個模型各做 10 個代表性的聲音（步槍、雷射、爆炸、機甲腳步、QB、機獸吼叫、近戰命中、蓄力、介面、環境音），使用者試聽決定模型 |
| 1 工具 | 產生腳本、提示詞表、自動評分、試聽頁 |
| 2 武器與命中 | 17 種武器配方、爆炸四層、依材質的命中、近戰 |
| 3 機體 | 依腳部類型的步伐、伺服、推進器、QB、落地、受損 |
| 4 敵人的辨識度 | 各種敵人與 Boss 招式的預兆（蓄力、預警、閃避的推進器）、機獸的叫聲；拆掉共用的 `charge`／`heavy`／`laserBig` |
| 5 介面與環境 | 介面音、15 個主題的環境音、警報 |

素材量估計從 2.6 MB 增加到 6～10 MB（遊戲啟動後才載入的 `lib/sfx-assets.js`）。

## 5. 實作紀錄

### 第 0 期：試做（2026-11-22）

- `scripts/sfx-gen.py --trial`：10 個聲音 × 兩個模型 × 3 個候選（同一句英文提示詞），修剪前後的靜音、淡出、峰值 −1 dB，輸出到 `tools/sfxgen/trial/`，`index.html` 是並排的試聽頁（含目前遊戲裡對應的舊聲音）。
- 結果（RTX 4070 12 GB、系統記憶體 32 GB）：Stable Audio Open 每個聲音 3 個候選一次產生約 70 秒（顯示卡最多 11 GB）；MOSS 每個候選約 37 秒（最多 9.3 GB），不論要的長度都對 30 秒的潛在空間去噪再裁切。
- **MOSS 的坑**：
  - 載入後 DiT 是 fp32（14.5 GB 超出 12 GB 的顯示卡、慢 10 倍）。不能 `.to(bfloat16)`，會把複數的位置編碼 freqs 變成實數。`sfx-gen.py` 的 `bf16()` 只轉浮點的參數與緩衝區。
  - 原本的 `from_pretrained` 用 `load_file` 讀進 5.6 GB 的 fp32 權重，再建一份 fp32 的 DiT。系統記憶體的高峰太高，Claude Code 會以記憶體不足停掉背景程序。`gen_moss` 換掉 `wan_audio` 模組的 `load_file`（逐一讀、轉 bf16），並以預設型別 bf16 建立 `WanAudioModel`（位置編碼明確用 float64 算，不受影響）。
  - 兩個模型分開跑（`--model=sao`，再 `--model=moss`），不要同時載入。
