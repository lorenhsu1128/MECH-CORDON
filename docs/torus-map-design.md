# 無邊界地圖（上下左右相接）

2026-11-22 使用者定案（分支 `torus-map`）：地圖改成無邊界的感覺——右邊接左邊、上邊接下邊（環面）。

- 範圍：**全部地圖**（自由出擊、主線、多人、Boss、機獸…）。
- 原本不適合的地圖（公路／鐵路、水壩、虛空、方舟、地下）**改造成能相接**。
- 地圖**一起放大**（繞一圈回到原地，太小會一直看到重複的景物）。

## 1. 架構

### 1.1 座標不設邊界，所有東西搬到「離參考點最近的那一份」

地圖的內容只有一格（邊長 S，產生時的座標是 −S/2～S/2，叫**原格**）。遊戲中的座標不取餘數、不設上下限：
玩家一直往 +x 走，x 就一直變大，永遠不會被瞬間搬走。其他東西每格（或每隔一段距離）檢查一次：
離參考點 F 在某一軸上超過 S/2（＋緩衝 `WRAP_HYS`）的，整個搬 ±S 到比較近的那一份。

- 參考點 F（`world.fx`／`world.fz`）：單人與客機＝自己的機體（過場、預覽器＝鏡頭）；多人的房主＝
  讓「切口」（F ± S/2）落在玩家之間最大空隙的中心（第 7 期；之前先用房主自己的機體）。
- 被搬的東西都離 F 半張地圖以上（S/2 ≥ 480 m，在霧裡、超出所有互動距離），所以**玩家附近的程式完全不用改**：
  距離、方向、碰撞、射線照舊用一般的歐氏幾何（全專案 1050 處的距離計算不動）。
- 不採用的做法：①座標取餘數＋每個距離計算改成繞行距離（要改的地方太多、漏一個就是 bug）；
  ②地圖外圍多複製一圈（可破壞物件要兩份同步、物件數 2.5 倍）；③玩家走到邊緣瞬間搬到另一邊（整個世界要
  同一格一起搬，粒子、軌跡、鏡頭狀態都要列舉，漏了看得到）。

### 1.2 三種資料的處理

| 種類 | 例子 | 處理 |
|---|---|---|
| 解析函式（由座標算出結果） | `terrainHeight`、`isVoid`、`onCorridor`、`offLimits`、`isReserved`、`waterDepth` | 函式開頭把輸入換回原格（`world.cx(x)`／`cz(z)`） |
| 靜態資料（產生時寫死座標的陣列） | `obstacles`、`props`（命中形狀）、`ramps`、`occluders`、場景裡的網格 | **搬資料**：`World.wrapData(F)` 掃陣列，逐項搬 ±S；網格由 `World.wrapView(C)` 依鏡頭掃 `scene.children` |
| 動態（遊戲端的東西） | 機體、投射物、掉落物、地雷、區域效果、裝置、出口、小人、地圖載具 | `Game.wrapTick()`（`game/torus.js`）每格把各類的資料位置搬到 F 附近；機體用 `MechEntity.shiftBy` 連同它記著的位置一起搬 |

- 回傳位置的解析函式（`corridorPoint`、`safePoint`、`spawnPoint`…）回傳離 F 最近的那一份（`world.ix(x)`／`iz(z)`）。
- `obsGrid` 的格子索引取餘數（S 是格子邊長的整數倍），資料搬了不用重建。
- 跨整張地圖的網格（地形、公路的路面、合併的甲板…）不能整個搬：產生之後 `World.tileize()` 依格子（`TILE_CELL`）
  切成小塊；地形一開始就分塊建。超過上限又切不了的群組在測試模式列出來，逐一處理。
- 粒子（顯示卡的緩衝）、軌跡不搬：只在玩家附近看得到，永遠到不了切口。
- 原本「以原點為中心」寫死的地方（`±world.lim`、`rnd(-R, R)` 再和玩家比距離、`world.zone` 的四個數）要改成以 F 為中心：
  `world.zone` 在相接的地圖是 F 周圍的一格（存取子），`inZone` 一律 true、`zoneExcess` 一律 0、`collide` 不夾住。

### 1.3 看得到多遠

- 物件只在離鏡頭 S/2 以內出現（每個物件只有一份）；更遠的只畫**遠景地形**（同一份高度圖重複取樣的低解析度環，
  取代原本邊界外的山脊與剪影），所以霧的最遠距離夾在 S/2 × 1.1 以內。
- 地圖大小：一般 `TORUS_SIZE`＝960 m（原本 690 m、可以走的 570 m）、大地圖 `TORUS_BIG`＝1260 m（原本 960／794 m）。
  相接的地圖 `k`＝S／124，所以原本寫成 `±62k` 的範圍就是整格；物件數照面積增加（約 2.5～2.8 倍）。

### 1.4 地形怎麼接

- 自然地形（雜訊、台地、沙丘、冰湖、變體的地形修改）：照舊算出不相接的高度 H，在接縫兩側寬 `SEAM_B` 的帶子裡
  和另一側往外延伸的 H 交叉淡化（`seamBlend`），不用逐一改每個地形函式。
- 有結構的地形（方舟的甲板、洋上都市的街區、水壩、Lattice-9）：版面本身要設計成週期的（各主題自己處理，第 4 期）。
- 物件放在原格裡；產生時的重疊檢查不繞過接縫，所以大型物件的中心離接縫至少半個物件寬。
- 沿軸或 45° 的公路／鐵路／河道本來就會自己接起來：彎度改成兩端斜率為 0 的週期函式、拿掉兩端的隧道口。

### 1.5 多人

- 每一端各自以自己的 F 搬資料；快照裡的位置收到時搬到自己的 F 附近（`applyEnt`），插值的目標取離目前位置最近的那一份。
- 房主送的特效與事件的位置照房主的座標；客機離房主的切口很遠時不會有差別，玩家分散超過半張地圖時
  遠處的特效可能畫在另一份（看不到），可接受。

## 2. 分期

每個主題改好才打開（主題的 `torus: true`；沒打開的照舊有邊界），最後一期全部打開並拿掉舊的邊界程式。

1. **核心**：World 的相接模式（大小、`k`、`cx`／`ix`、分塊的地形、接縫淡化、遠景環、`wrapData`／`wrapView`、
   `obsGrid`）、`Game.wrapTick` 與 `MechEntity.shiftBy`、霧；先打開模擬訓練場與 world.js 裡的自然地形主題
   （礦坑、荒野、冰原、沙丘），地形特徵與公路先做成能接的版本。測試：`?tile=K`（從第 K 格開始玩，
   座標都很大，抓得到「以原點為中心」的假設）＋自動玩家繞地圖一圈。
2. **遊戲規則**：出生點、增援（邊緣進場改成視線外）、敵群、據點、出口、作戰區域的 HUD 與推回、雷達、鎖定。
3. **其他主題**：貨運集散場、淹沒城區、宇宙港、研究特區、火山、Lattice-9、洋上都市、高空軌道、水壩、方舟、空域；
   各主題的變體與地標。
4. **Boss 與機獸**：用到角落、邊界、隧道的招式（電磁砲台、推土要塞、高速突擊機、武裝列車、作戰區域縮小…）。
5. **主線**：狹長／小型／分段開放的作戰區域、各區段類型、地圖載具、小人、地圖裝置、轉場的出生點。
6. **多人**：快照、房主的 F、`NET_VERSION`。
7. **自訂關卡與編輯器、作戰室的戰略桌、地圖預覽器、過場動畫的地圖**。
8. **收尾**：全部打開、拿掉邊界的舊程式、冒煙測試、卡頓檢查、文件。
