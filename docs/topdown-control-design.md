# 俯視的「面向游標」操作

2026-11-06 使用者定案：俯視視角的移動與自動鎖定改成接近追尾視角的方式；舊的操作保留成設定的選項。

## 定案

- **設定**「俯視的操作」`ctrl.topCtl`：`aim` 面向游標（預設）／`classic` 傳統（舊的螢幕方向移動、滑鼠瞄準、正面 180° 鎖定）。舊的「瞄準」`ctrl.aim` 與「移動方向基準」`ctrl.moveRel` 只在傳統時顯示（`settings.js` 的 `setTopRows`）。
- **鏡頭**照舊固定朝北，不轉。
- **移動**：機體一直面向游標（`fpFace`）；上／下＝往游標前進／後退、左／右＝側移。基準方向是「機體到游標（吸附時是目標）」的方向，不是機體目前的朝向（轉身有速度限制，用游標方向才不會慢一拍）；游標離機體 `NEAR_D` 以內時保留上一次的方向。
- **自動鎖定**：追尾的鎖定框（`chase.js` 的 `chaseLockCands`／`chaseAutoLock`，大小照火控），中心改成準星（`lockBoxCenter`）；框裡離準星最近的優先、目標離開框 0.35 秒換。俯視不做追尾的目標輔助（鏡頭轉向、甩動換目標）。
- **游標吸附**（`ctrl.topSnap`，預設開）：取代目標輔助。
  - 滑鼠：游標在畫面上離敵人的中心小於「鎖定框半寬 × `SNAP_K`（0.35）＋目標在畫面上大小的一半（上限 0.4 個半寬）」時吸附並立刻鎖定；已經吸住的要離開到 `SNAP_OUT`（1.6）倍才放開。幾台都在範圍內時吸最近的。只吸攻擊距離內、可以鎖定、不是陷阱弱點與可以打掉的投射物、沒有被煙霧擋住的。
  - 吸住時：準星在 `RET_T`（0.1 秒）內滑到目標上（系統游標的位置畫一個小點），瞄準點、面向、移動的基準都改成目標。
  - 切換鎖定鍵（`cycleLock`）會放開吸附，游標移開 `NOSNAP_PX` 之前不重新吸附（否則下一格又吸回去）。
- **手把**：右搖桿當游標——推的方向＝機體面向與準星（機體前方 `DIR_D`＝24 m×DS），放開保持最後的方向；左搖桿照移動。吸附看角度：相差 12° 內吸附、偏離 20° 才放開。
- **觸控**：俯視時也顯示右搖桿（`body.rstick`），用法和手把相同；攻擊鍵照舊獨立（不像追尾兼在右搖桿上）。觸控的自動攻擊只打鎖定框裡的目標。

## 實作

- `game/top-aim.js`（mixin）：`topAim()`（俯視＋面向游標；空域、觀戰不算）、`moveRelOn()`／`moveYaw(p)`（移動的相對基準，`player.js`、`mp-client.js`、`tutorial.js` 的 `tutKeyVec`／`tutAxes` 共用）、`lockBoxCenter()`、`topAimInput(p, dt)`（每格：游標的世界點與畫面位置、吸附 `topSnapTick`、準星 `topRet`、面向 `topYaw`、`autoLock`）、`topSnapRelease()`、`drawTopAimHud()`；狀態 `topDir`／`topSnap`／`topRet`／`topYaw`／`topNoSnap`，`setView`／`viewReset` 時 `topAimReset`。
- `reticlePoint`（game.js）在面向游標時用 `topRet`，光束武器的瞄準點跟著吸附。
- 切換鎖定（`cycleLock`）在面向游標時依離機體的遠近換（框裡的候選本來依離游標排序，但游標跟著目標走，照那個順序只會在最近的兩台之間來回）。
- 吸附住的目標不在 `lockPool` 裡（移除了但沒有標成擊破）就放開。
- 近戰／遠程訓練的示範與自動操作（`tut.scr` 在動）：腳本以「機體對著假人」寫移動與按鍵，所以游標由 `topAimOverride` 決定＝鎖定中的假人（`tut.dummies` 之一），否則是這一步的假人。玩家自己操作的練習照常用游標。
- 順便修掉 `tutorial.js` 的 `tutKeyVec` 的舊 bug：`fwd.multiplyScalar(-z)` 先改掉了 `fwd`，相對移動時「側」算成 0（追尾或「機體面向」時的示範也受影響）。
- 多人：客機輸入的 `fp` 3＝面向游標（房主設 `fpFace`；光束照俯視：有鎖定打目標、否則準星）；吸附只在本機算，結果是鎖定與移動方向，照原本的輸入送出。`NET_VERSION` 11.27。
- 冒煙測試：`testTopAim`（面向與相對移動、跟著游標的鎖定框、吸附與遲滯、最近的、切換鎖定後放開、設定關閉、手把的角度吸附、實際的滑鼠、截圖 `topaim-snap.png`）。其他舊的測試照傳統操作寫的，測試環境沒有存過設定時預設 `topCtl: 'classic'`（`smoke-test.js` 的 `newContext` 包裝；設定畫面的測試 `realDefaults` 用真正的預設）。
