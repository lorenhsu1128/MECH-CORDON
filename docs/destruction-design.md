# 地圖物件的破壞：分段受損、殘骸、倒塌

2026-11-02 使用者定案：地圖上的物件全部可以破壞，而且不是一擊就碎掉。每個物件都有自己的生命值，看得出不同程度的損傷，直到完全損毀；完全損毀後在原地留下殘骸。

## 定案

| 項目 | 定案 |
|---|---|
| 外觀的做法 | **方案三＋方案二**：<br>・方案三（全部物件）：建造時把物件分成主體與附件，越打附件掉得越多，高的物件一段一段變矮，主體焦黑、冒煙。<br>・方案二（重要物件）：另外補專屬的受損與殘骸造型。 |
| 大型結構 | **乙**：標出承重柱，承重柱全壞時預警，之後往一個方向倒下，壓到的敵我都受傷，倒下後變成橫躺的殘骸。 |
| 平台與橋 | 承重柱全壞時會倒，上面的物件掉下來摔壞，機體落地。**例外**：跨在虛空上的橋只打到重損，不會斷。 |
| 跟地形連在一起的巨型結構 | **可以局部打穿**：壩體、Grid 086 的甲板格子、隧道口、岩頂、地形島的外緣。 |
| 範圍 | 一般物件、地形特徵、各主題的大型結構、72 個地標、Boss 關，全部納入。 |
| 踩平 | 要做：2 m 以下的雜物被機甲走過或 QB 撞到，直接變成殘骸。 |
| 屬性倍率 | 要做：依物件的材質，對實彈、爆發、能量給不同的傷害倍率。 |
| 起火 | **不是所有物件都會起火**：只有含燃料或可燃的物件會起火。其他物件依材質改成冒煙、火花、粉塵、蒸氣，見「材質表」。 |

## 參考的作法

- **依血量換受損狀態，最後換成殘骸**：
  - Battlefield 6：重做了血量狀態的轉換系統，每次轉換都可以掛自訂的邏輯；殘骸留在地圖上，改變可以走動的空間。
  - Company of Heroes 3：最多 3 個受損狀態；碎片會變成新的掩體，也會打開或封住通道。
  - MechWarrior 5：建築由可以各自破壞的模組組成；機甲可以直接踏穿建築，但會減速。不同武器對建築的效果差很多：飛彈很有效，雷射幾乎沒用。
- **承重結構與倒塌**：
  - Red Faction Guerrilla：承重部件被打掉夠多時，建築在自己的重量下倒塌。
  - Battlefield 4：把支撐柱設計成「預先削弱」，讓玩家選擇要不要弄倒整棟建築。
  - Daemon X Machina：可以把建築推倒，壓在敵人身上。
- **反面教材**：Mercenaries 2 被批評瓦礫消失得太快，倒下的建築也不會連帶壓到別的建築。
- **網路同步**：
  - 只同步受損狀態，碎片與煙塵各端自己做。
  - 中途加入的玩家要補送整張狀態表（Teardown、Battlefield 6 的做法）。
- **不採用**：預先碎好的碎塊加剛體物理（The Finals、Teardown）。網頁跑不動，多人也很難同步。

## 現況（改版前）

- **兩種狀態**：物件只有一段血量。
  - 登記：`World.regProp`
  - 受傷：`Game.damageProp`（`game/map-extras.js`）
  - 擊破：`World.destroyProp` 拿掉碰撞、隱藏群組，再呼叫 `fx.shatterProp`
  - 碎片落地後由 `debrisPieces` 合併成一塊永久的碎石網格，沒有碰撞。
- **碎片不分大小**：除了貨櫃、卡車、岩石，其他物件一律噴 6 根 0.6 m 的小方塊。
- **打不壞的東西**：
  - 地形特徵：`addDeck`／`addPillar`、高台、坡道、隧道口
  - 疊三層以上的貨櫃堆、倉庫
  - 各主題的 `buildStructures`
  - 地標
  - 直接 push 進 `obstacles` 的物件
- **材質**：不透明的類別材質（`detail.js` 的 `classMat`）與 `mat()` 是全域共用的，只有可淡出的材質每個物件各一份。所以受擊閃光只對可淡出的材質有效。
- **既有的 bug**：
  1. 客機上，物件碎裂時爆炸與煙塵出現兩次：房主 `shatterProp` 裡的 fx 被轉送給客機，客機收到 `propDie` 之後又自己跑一次。
  2. EMP 光束每一格送一次 `propHp` 事件，並建立一個 `setTimeout`。
  3. 斷線 60 秒內重連的玩家與觀戰者（`sendMissionState`）收不到物件狀態，被打壞的物件會變回完好，碰撞也不一致。
  4. 自訂關卡的 `setPlacedVisible(true)` 會讓已經打壞的物件重新出現。

## 受損的階段

各端都由血量比例決定階段。房主送血量，客機由血量推算階段，所以階段本身不用同步。

| 階段 | 血量 | 外觀 | 碰撞 |
|---|---|---|---|
| 0 完好 | > 75% | — | 原本的 |
| 1 輕損 | ≤ 75% | 彈痕、焦黑一點；第 1 批附件脫落（天線、燈、欄杆） | 不變 |
| 2 中損 | ≤ 50% | 焦黑加深，依材質的持續效果開始（冒煙、火花、粉塵、蒸氣）；第 2 批附件脫落（外板、門、上層的小零件） | 不變 |
| 3 重損 | ≤ 25% | 依材質的濃煙或起火；高的物件塌掉最上面一段（變矮）；第 3 批附件脫落 | 高度降到塌掉之後的高度 |
| 4 殘骸 | 0 | 主體換成殘骸造型，噴出依尺寸的碎片；殘骸冒煙（可燃的繼續燒一陣子） | 換成殘骸的碰撞（較矮、較寬） |

- 殘骸不再受傷，整場保留。
- 地圖物件不設遲滯：血量只會減少，不會在兩個階段之間來回跳。修理類的效果不作用在地圖物件上。

## 材質表

每個物件種類指定一種材質，材質決定以下幾件事：

- 對三種屬性的傷害倍率
- 第 2～4 階段的持續效果
- 會不會起火
- 碎片的樣子
- 命中與倒塌的音效

| 材質 | 例子 | 實彈／爆發／能量倍率 | 持續效果 | 起火 | 碎片 |
|---|---|---|---|---|---|
| 混凝土 `concrete` | T 型牆、擋牆、防爆牆、斷牆、壩體、高台、機房 | 0.6／1.6／0.5 | 粉塵、落下的碎塊 | ✗ | 灰色碎塊、鋼筋 |
| 鋼骨金屬 `metal` | 貨櫃、倉庫、鐵塔、桅杆、料斗、拱屋、太陽能板、散熱板 | 0.8／1.3／0.7 | 黑煙、火花 | ✗ | 鐵板、型鋼 |
| 燃料 `fuel` | 儲槽、燃料槽、燃料車、油桶、汙染物桶 | 1.0／1.5／1.0 | 漏液與黑煙；第 3 階段起火 | ✓（第 3 階段起；損毀時二次爆炸） | 鐵板＋火球 |
| 車輛 `vehicle` | 車、公車、卡車、有蓋貨車、MT 殘骸 | 0.9／1.4／0.9 | 冒煙；第 3 階段引擎蓋冒火 | ✓（小火，只在車頭） | 車殼、輪胎 |
| 電氣 `electric` | 變壓器、路燈、照明塔、雷達、信號燈桿、防空砲塔 | 0.8／1.3／1.2 | 電火花、燈閃爍熄滅 | ✗（變壓器在損毀時爆一次電弧） | 鐵板、玻璃 |
| 岩石 `rock` | 岩石、岩柱、砂岩、落石堆、消波塊、鹽塊 | 0.5／1.6／0.4 | 粉塵、落下的碎石 | ✗ | 岩塊 |
| 冰 `ice` | 冰塊、雪牆 | 0.7／1.3／1.5 | 冰屑、白霧 | ✗ | 冰塊（半透明） |
| 木與植物 `wood` | 針葉樹、棚屋、花台、木箱 | 1.0／1.3／1.2 | 木屑；第 3 階段起火 | ✓ | 木片、樹枝 |
| 玻璃帷幕 `glass` | 洋上都市的高樓、研究棟 | 1.0／1.4／1.0 | 碎玻璃落下、閃光 | ✗ | 玻璃片＋型鋼 |
| Coral `coral` | Coral 結晶、Coral 收容槽 | 0.8／1.2／0.6 | 紅色的光粒 | ✗（損毀時爆一次 Coral 光） | 發光的結晶碎片 |
| 管線 `pipe` | 管線、管線束、高架管線 | 0.9／1.4／0.9 | 蒸氣噴出（依位置） | ✗（除非是油管：`fuel`） | 管段 |

- 材質由 `data/destruct.js` 的 `PROP_MAT[種類]` 指定，沒有指定的依主題的 `propMat` 預設，再沒有時算 `metal`。
- 倍率疊在現有的屬性系統上：`takeDamage` 的第 8 個參數，沒有時依武器 id 推算。
- 打中時的回饋依材質變化：火花、粉塵、木屑、冰屑等特效與命中音效。這樣玩家看得出「這把武器對這個物件有沒有效」。
- 只有 `fuel`、`vehicle`、`wood` 三種材質會起火。其他物件到第 4 階段也只有煙、火花或粉塵。
- 自訂關卡的擺放物在物件定義加 `mat`，關卡編輯器顯示它，但不讓玩家改。

## 血量

- **現有的可破壞物件**：保留現在的數值當基準。
- **新加入的物件**：依尺寸等級（`docs/world-scale.md` 的掩體分級）與材質算出，等於「材質係數 ×（外框表面積的量級）」，再限制在等級的範圍內。

| 等級 | 範圍 | 例子 |
|---|---|---|
| 雜物（≤ 2 m） | 300～1,500 | 機甲可以踩平 |
| 低掩體（2～4 m） | 1,500～4,000 | |
| 半身掩體（4～7 m） | 3,000～9,000 | |
| 全身掩體（≥ 10 m） | 8,000～20,000 | |
| 承重柱（每根） | 4,000～12,000 | |
| 地標 | 承重柱合計約 30,000～60,000 | |

- 第 1 期以靶場量測校正：用一般的組裝，中型掩體大約打 5～10 秒到殘骸，倉庫大約打 20～30 秒到倒塌。

## 方案三：零件分批脫落（全部物件）

- **在建造時分組**：`PK` 加一個 `dmgTier(n, fn)`。在 `fn` 裡加入的零件屬於第 n 批附件（1～3），合併時另外成一組網格，掛在 `group.userData.dmg`（不是 userData 本身；比照 `rig.dmg`，放在 WeakMap 或群組屬性）。
  - 沒有標記的零件是主體。
  - 附件到了它的階段才拆下來拋出：沿用 `foe-damage.js` 的 `detach`＋`fling`，碎片落地後淡出。
- **變矮**：主體可以用 `dmgCut(y)` 標出第 3 階段塌掉之後的高度。
  - 建造時，切線以上的主體零件分到第 3 批，第 3 階段時拆掉。
  - 同時把碰撞的 `top` 與命中形狀（`propShape`）改到新的高度。
  - 疊放的物件以層為單位，例如貨櫃堆：第 3 階段掉最上面一層，殘骸剩最下面一層壓扁。
- **焦黑**：物件第一次受傷時才把材質複製一份（`ownMats`，延遲到受傷才做，所以沒被打的物件不增加成本），之後依階段把顏色變暗。主體與殘骸都用這一份。
- **沒有標記的物件**（舊的程式模型、GLB）：
  - 自動依外框把最上面 25% 當第 3 批（變矮）。
  - 附件改成噴出同色的碎板（和 `foe-damage.js` 沒有 `plates` 時的做法一樣）。
- **補標記的方式**：逐一走過 `prop-models.js`、`cover-models.js`、`themes/*.js`、`variants.js`、`landmarks.js` 的建模函式補上 `dmgTier`／`dmgCut`。

## 方案二：專屬的受損與殘骸造型（重要物件）

- **殘骸**：每個物件種類可以有自己的殘骸建模函式 `WRECK[種類](p, h)`（純函式，`h` 是以物件編號算出的雜湊亂數）。
  - 沒有專屬造型時用通用殘骸 `wreckGeneric`：依外框做出壓扁、傾斜、缺角的底座，加上依材質的碎塊堆；可以沿用地標工具的 `rubble`、`scorch`、`plated`。
- **受損造型**：少數物件另外有第 2～3 階段的專屬造型（例如貨櫃凹陷、門脫落；路燈彎折；車子爆胎、車身塌陷）。到該階段時換掉主體。
- **優先做的種類**（出現最多、最顯眼）：

| 類別 | 種類 |
|---|---|
| 貨櫃類 | 貨櫃、貨櫃堆、有蓋貨車 |
| 車輛類 | 車、公車、卡車、燃料車、MT 殘骸 |
| 燈與桿 | 路燈、照明柱、照明塔、信號燈桿、天線桿、通信桅杆 |
| 儲槽類 | 儲槽、燃料槽、Coral 收容槽 |
| 牆類 | T 型牆、防爆牆、紐澤西護欄、斷牆 |
| 其他 | 倉庫、拱屋、棚屋 |

- **GLB**：模型庫為每個物件多兩種槽位，`prop/<種類>_dmg`（重損）與 `prop/<種類>_wreck`（殘骸）。有 GLB 時用 GLB，沒有時用程式模型。
  - 主體是 GLB 時，焦黑與冒煙照樣作用。附件脫落只對程式模型有效，GLB 改用噴出同色碎板。

## 殘骸

- **碰撞**：殘骸換成較矮、較寬的碰撞方塊或圓柱。
  - 高度原則上不超過「跨越的門檻」（`STEP_H` 1.8 m），機甲可以直接走過去，殘骸主要用來擋子彈。
  - 倒下的高聳結構與大型建築的殘骸可以比較高（4～7 m 的半身掩體），因為 AI 沒有導航網格，靠轉向與 `collide` 就能繞過。
- **視線**：殘骸換掉碰撞後，`losBlocked`、`hitsWorld`、`propBlocks`、鏡頭遮擋都自動用新的形狀。
- **碎片的上限**：
  - 拋出的碎片照舊落地後淡出。
  - 永久留在地上的小碎石（`debrisPieces` 的合併網格）全場最多 40 塊，超過時最舊的慢慢沉進地面。
  - 殘骸本身不算在上限裡。
- **效能**：殘骸是最後的狀態，不會再變，所以每累積幾個就併成一個靜態網格（同 `mergeStatic`，分區合併），控制繪製次數。
- **地上的痕跡**：損毀的位置留下焦痕或粉塵痕。沿用 `bulletMark` 的做法，但不會淡出；全場上限 60 個。

## 踩平

- **對象**：雜物等級（高 ≤ 2 m，或材質表標成 `crush` 的：護欄、路燈、油桶、車、花台、針葉樹、信號燈桿）。
- **觸發**：機甲（玩家、敵人、友軍）的腳或身體撞到它，或用 QB／突擊推進撞上去，直接變成殘骸。
  - 不算傷害數字，也不給賞金。
  - 戰車腳、四足腳的範圍比較大。
- **回饋**：
  - 機甲的速度 ×0.85，持續 0.3 秒。
  - 依材質的碎裂音效、揚塵、碎片往前噴。
  - 只有玩家撞到時，鏡頭小晃一下。
- **判定**：只在房主或單機判定，用現有的 `propDie` 事件（多帶一個 `cr` 表示被踩平，客機改用往前噴的碎片）。

## 承重柱倒塌（乙）

- **結構**：高聳結構與有東西站在上面的結構，由一個「結構」與 1～4 根「承重柱」組成。
  - 承重柱各自是一個可破壞物件，有自己的血量與受損外觀，打得到也鎖定得到；名稱寫成「<結構名>的支柱」。
  - 結構本體也可以受損，但打本體不會讓它倒下，只會掉外板。
- **倒塌的流程**：
  1. 最後一根承重柱損毀時，結構發出聲音、搖晃、掉碎塊。
  2. 地上出現倒下範圍的預警帶，持續 1.5 秒（`fx.warnRect`，會轉送給客機）。
  3. 結構倒下，大約 1.2 秒，依樞軸旋轉的動畫。
  4. 預警帶裡的機體受到爆發傷害（依結構大小，2,000～6,000），並且失衡。
  5. 煙塵往外擴散，換成橫躺的殘骸，碰撞也一起換掉。
  6. 倒下的範圍裡的其他地圖物件受到同樣的傷害，可能連帶損毀或倒塌。
- **倒下的方向**：依最後一擊的方向（從攻擊者往外）。在可以倒的方向（建造時標出，避開地圖外與保留區）裡選最接近的，所以玩家可以刻意讓它倒向敵人。
  - 方向由房主決定，用事件 `pcol { i, d }` 送給客機。殘骸的造型由物件編號的雜湊決定，所以各端一致。
- **對象**：
  - 獨立的高聳結構：輸電鐵塔、照明塔、鑽井架、煙囪、天線、雷達、發射塔、管制塔、洋上都市的玻璃高樓、技研都市的頂天岩柱
  - 地形特徵的橋、高架、掩體群
  - 大型建築：倉庫、機庫、研究棟
  - 地標
- **平台與橋**：
  - 倒下時，上面的地圖物件掉下來並受到傷害，通常直接變成殘骸。
  - 站在上面的機體落地：碰撞拿掉之後，照一般的掉落處理。
  - 上面的小人一起掉落死亡，比照現有的爆炸死亡。
  - 連到它的坡道一起移除。
  - **虛空上的橋例外**：只打到重損（第 3 階段）就不再掉血，`isVoid` 不受影響。
- **地標**：每個地標在設計時標出 2～4 根承重柱，例如斗輪機的履帶與支臂、發射塔的腳。地標的造型工具加 `support(...)` 讓建模時一起登記。

## 巨型結構的局部打穿

跟地形連在一起的結構分成若干段，每段各自有血量。打穿一段只改變那一段，主體不會整個倒下。

| 結構 | 分段 | 打穿之後 |
|---|---|---|
| 多重水壩的壩體 | 沿壩體每 12～16 m 一段 | 缺口；上游有水時，從缺口噴出水流（沿用閘門的水流 `addFlow`，往下游推、受傷） |
| 水壩的閘門 | 每一扇 | 門楣掉落，閘門變成通道 |
| Grid 086 的甲板 | 甲板格子的每一格 | 那一格掉下去，變成洞（上面的物件跟著掉）；格子的支柱是承重柱，四角的支柱全壞時那一格也掉 |
| 隧道口 | 每一個 | 坍方：入口被岩塊半掩，變成掩體；武裝列車的隧道不會被封住，只剩外觀 |
| 地下的岩頂 | 依格子分區（約 20 m） | 開洞：落石、光柱照進來，霧變淡一點；不影響碰撞（岩頂本來就沒有碰撞） |
| 地形島的外緣 | 外緣一圈的護欄與外緣平台 | 崩落：外緣的護欄與平台掉進虛空，地形本身不改；不會把街區切斷 |

- **限制**：
  - 打穿不能讓出生點、出口、目標、補給台變成無法抵達。生成時把這些位置附近的分段標成「只受損」。
  - Boss 的場地、武裝列車的鐵路、水壩閘門砲台的閘門（閘門砲台在場時）也標成只受損。
- **地形**：壩體、甲板本身是障礙物或 deck，打穿就是把那一段換掉，不改高度圖。不改 `world.h`，所以多人不必同步高度圖。

## Boss 關與其他系統

- **Boss 關**：照舊是開闊的場地（`openArena`）。Boss 的攻擊也會打壞物件。
  - 推土要塞的衝撞改成一次讓物件進入殘骸（之前是直接碎掉）。
  - 廢鐵合成體吸附物件時，物件直接變成殘骸。
  - Boss 場地效果的新掩體（`addTempWall`）改用同一套受損外觀與材質。
- **小人**：
  - 站在物件上的小人，物件變矮或損毀時掉下來。
  - 圍著物件做事的小人，物件損毀時受驚逃跑。
- **持續特效**（`fx-ambient`）：物件進入殘骸時停止。可燃的殘骸改成燃燒一段時間。
- **自訂關卡**：
  - 擺放物的 `hp > 0` 照舊。物件定義加材質與殘骸。
  - 編輯器的單位設定可以把物件設成「不可破壞」。
  - 觸發器的事件「物件損毀」照舊，另外加「物件進入第 n 階段」。
  - 修正 `setPlacedVisible` 的 bug。
- **AI**：
  - 沒有導航網格，碰撞換掉之後轉向就會自動繞過，不用另外處理。
  - 掩體被打成殘骸後，視線打開，敵人的察覺照常運作。

## 多人同步

- **血量**：房主在每次快照的時候，把這一格血量有變的物件合併成一個 `propHp` 陣列 `[[idx, hp]…]`，取代每次命中各送一個事件（修正 EMP 的事件洪水）。客機由血量推算階段，自己演出。
- **事件**：
  - `propDie`：多帶 `cr`（被踩平）與 `d`（損毀時的衝擊方向，碎片往那邊噴）。
  - `pcol { i, d }`：倒塌。
  - `pseg { i }`：巨型結構的分段打穿。
- **特效只在各端自己做**：`shatterProp` 與受損的特效一律以 `local()` 執行，不轉送給客機，修正客機上特效出現兩次的問題。
- **狀態表**：`sendMissionState`（重連、觀戰）與房主遷移時，送全部物件的 `[血量, 狀態旗標]`（幾百個物件不到 2 KB）。收到時直接套用到最後的階段，不播過程。
- **決定性**：
  - **新加入的物件一律在生成結束後登記**，依 `obstacles` 的順序加在現有物件的後面，所以現有物件的 `idx` 不變。
  - 登記與殘骸造型都不呼叫生成用的亂數。殘骸用物件編號與地圖種子的雜湊（`hashRng`）。
  - 附件的分組在建模時就決定，不呼叫亂數。
- **協定版本**：提高 `NET_VERSION`。

## 效能

- **材質**：沒受傷的物件不多花任何成本；材質到第一次受傷時才複製。
- **網格**：附件的網格只有程式模型有。遠處（大約 120 m 以外）的物件改成噴同色碎板，不拆附件。
- **持續效果**：煙、火、火花、蒸氣的發射器全場只留離鏡頭最近的 12 個；其他只在進入新階段時噴一次。
- **殘骸**：分區合併成靜態網格。
- **量測**：每一期都用 `node scripts/model-bench.js` 比較改版前後的繪製次數與幀時間，目標是全部打成殘骸的情況下，幀時間不超過改版前的 +10%。冒煙測試另外量「全場物件都打到第 3 階段」的幀時間。

- **切三角形**（`world/prop-split.js` 的 `splitTris`）：

- **標記 API**：

- **其他物件**：先用自動處理，第 7 期補專屬造型時再一起標記。

### 第 3 期：踩平（2026-11-02）

- **判定**：`game/destruct.js` 的 `propCrushTick`，每格在房主／單機執行，接在主迴圈的 `updateHazards` 之後。
- **哪些物件可以踩平**：`data/destruct.js` 的 `propCrushable`。
  - `CRUSH` 列出的種類：護欄、燈桿、路燈、信號燈桿、針葉樹、花台、油桶、車、防風牆、天線桿。
  - 其他高 2.6 m 以下、長 14 m 以下的物件。
  - 清單在換地圖時建立一次，損毀的物件從清單移除。
- **觸發**：
  - 機甲（`crowdMechs`：玩家、敵人、友軍、載具；飛在空中的不算）要在移動中（水平速度 ≥ 1 m/s），腳的高度不能比物件頂高出 1 m 以上。
  - 碰到的距離是 `max(踩小人的範圍 + 0.3, 移動的碰撞半徑（radius × 0.8）+ 0.5)`。一定要比移動的碰撞半徑大，否則圓柱類的物件（燈桿）會先把機甲推開，永遠踩不到。
- **結果**：
  - 呼叫 `propKill(p, 方向, { cr: true })`：不跳傷害數字、不給賞金；`propDie` 事件帶 `cr`，客機改播往前噴的少量碎片與粉塵。
  - 殘骸是扁的：`p.crushed` 時高度 ≤ 0.45 m，也不留斷口。
  - 機甲的水平速度 ×0.85；玩家的機體另外小幅震動手把。
- **冒煙測試**：`testCrowd` 在改版前的版本就偶爾失敗（隨機地圖），單獨重跑三次有兩次通過，不是這一期造成的。

### 第 4 期：承重柱倒塌（2026-11-03）

- **登記**：`World.regStructs`，在 `regRest` 之後執行，不用亂數。
  - 對象：還沒登記的障礙物，依群組合成一個。來源是地形特徵、主題的大型結構、地標、很大的物件。
  - 不在這一期處理的：
    - 有甲板的群組
    - 有頂的圓柱
    - 坡道旁的
    - `seg` 的（水壩的壩體，第 6 期）
    - 撐著甲板的：`underDeck`，頂在甲板底 4 m 內、水平重疊（橋墩、橋下的牆、高架管線的腳；第 5 期）
  - 高不到 4 m 的照一般物件登記（「掩體」）。
  - 其他的分成兩種物件：
    - **結構本體**（`p.body`）：命中形狀從承重柱以上開始。`noDie`：血量最少留 1，所以只會受損到第 3 階段、不會因為傷害而損毀。`noCut`：不切上段。
    - **承重柱**（`p.support`、`p.of`＝本體）：結構底部的區域，高＝結構高度的 22%（2.5～9 m）；小的 1 根、長的 2 根（沿長邊）、大的 4 根（四角）。承重柱沒有自己的碰撞，結構的碰撞到倒下之前都不變。
  - 本體的血量＝承重柱合計 ×1.5，只決定外觀的階段。
- **承重柱的受損**（`propStageCheck`）：只噴碎板，不焦黑，因為模型是整個結構共用的，焦黑看本體的階段。
  - 承重柱損毀時（`propSupportDown`）：底部那一區的三角形碎掉拋出，加上揚塵與爆炸。
- **倒塌**（`propCollapse`）：最後一根承重柱損毀時，房主以 `propFallDir` 決定方向，送出 `pcol { i, d }`。
  - **方向**：四個軸向裡最接近最後一擊的方向，倒下後的頂端要在場地裡。
  - **寬的建築**（高 ≤ 寬 × 1.5）：`propSink`，往下塌成瓦礫堆。
    1. 預警框＝外框再往外 4 m，持續 1.5 秒，期間晃動。
    2. 2 秒內壓扁沉下去，周圍不斷揚起粉塵。
    3. 換成通用殘骸（`addWreck`，殘骸用倒塌前的整個外形 `shape0`）。
    4. 外框外 4 m 內與屋頂上的機體受到爆發傷害。
  - **細高的**：整個倒下。
    1. 模型掛在底邊的樞軸上（`attach`，保留世界座標）。
    2. 預警帶 1.5 秒、晃動，之後 1.4 秒加速倒下到 85°。
    3. 落地時沿倒下的方向揚塵、衝擊波、爆炸音。
    4. 碰撞換成橫躺的方塊：長＝結構高、寬＝原本另一個方向的寬、高＝原本沿倒下方向的厚度，最多 7 m。
  - **壓到的**（`propFallHit`，房主／單機）：
    - 機體受到爆發傷害（結構高 × 160，2,000～6,000），衝擊 1,500。
    - 範圍裡的其他地圖物件受到兩倍的傷害，可能連帶倒塌。
    - 小人以 `crowdBlast` 死亡。
- **同步**：
  - 血量表多一種項目 `[編號, 0, 方向]`（倒下的結構）。
  - `propApplyHp` 對結構本體只看方向，有方向時直接躺好或塌好（quiet）。
  - 客機收到 `pcol` 照同樣的方向演出（`propApplyCollapse`）。
- **地標**：沒有另外做造型工具的 `support`，地標照同樣的自動配置（依外框的四角）登記承重柱。
- **冒煙測試**：`testDestructCollapse`。
  - 水沒市街的大樓往下塌。
  - 宇宙港的發射塔倒下。
  - 只打本體不會倒。
  - 承重柱全壞才倒，並送出 `pcol`。
  - 壓到的玩家受傷。
  - 客機套用血量表時直接躺好。

### 第 5 期：平台與橋的倒塌（2026-11-03）

- **甲板**（`World.regDecks`，在 `regStructs` 之後）：只有甲板的群組（橋面、高架、掩體頂、輸送管線、虛空上的橋）登記成甲板本體。
  - 甲板本體的設定：`mode` 'drop'、`noDie`、`noCut`、`ramps`＝接著它的坡道（`rampsNear`：高端在外框頂 3 m 內、水平相接）。
  - 承重的：找撐著它的障礙物（頂在甲板底 4 m 內、水平重疊：橋墩、`addPillar` 的支柱、掩體群的牆），登記成獨立的物件（`sep`：有自己的模型與碰撞，損毀時照一般物件換成殘骸）。
  - 找不到時（輸送管線的腳在 `decorG` 裡），在甲板上沿長邊分 2～4 段當承重的區段（「橋面的接縫」，和甲板共用模型）。
- **虛空上的橋**（洋上都市、高空軌道）：地形低於 `void.y` 的就是。
  - 只看地形：`isVoid` 會把橋面本身當成地面，所以不能用它。
  - 沒有承重、`noCollapse`，最多打到第 3 階段。
  - 懸在虛空裡的支柱（有頂的圓柱）不登記。
- **上面站得了東西的建築**（`regStructs` 擴充）：
  - 甲板＋牆的群組（機庫、有平台的地標）一律往下塌（`forceSink`）。
  - 接著坡道的高台（地形特徵的高台）也一律往下塌，坡道的碰撞與模型一起拿掉（`propRampsOff`；高台的坡道記錄多了 `mesh`）。
  - `underDeck` 不算自己群組的甲板，否則機庫會被自己的屋頂當成「撐著甲板的」而略過。
- **甲板掉下來**（`propDrop`）：
  1. 預警框在甲板底下的地面，持續 1.5 秒，期間晃動。
  2. 1 秒內加速掉到中央的地面，稍微傾斜；橋會掉進底下的河道、壕溝，兩端埋進岸邊。
  3. 放在甲板上的物件掛在樞軸上一起掉。
  4. 落地後換成平放的碰撞：外框＝甲板，高＝甲板厚度，最多 2.5 m，機甲走得上去。
  5. 站在上面的機體因為碰撞拿掉而掉下來。
  6. `propFallHit`：放在上面的物件直接摔壞，其他範圍裡的機體與物件受到爆發傷害。
- **承重柱全壞的判斷**：多了 `noCollapse`。分開的承重（`sep`）不走 `propSupportDown`，因為它們不切共用的模型。
- **Grid 086**：甲板格子與它的支柱標成 `seg` 'grid'，留到第 6 期處理。
- **冒煙測試**：`testDestructCollapse` 多了兩項。
  - 集散場的橋面：站在上面的玩家跟著掉、橋墩換成殘骸。
  - 洋上都市虛空上的橋：沒有承重、打不斷。

### 第 6 期：巨型結構的局部打穿（2026-11-03）

- **登記**（`World.regSegs`，在 `regDecks` 之後）：每一段各自是一個物件（`p.seg`），沒有自己的碰撞；`destroyProp` 只標成損毀，由 Game 的 `propSegDown` 演出與改碰撞。
  - **壩體**（`seg` 'dam'，水壩主題建壩體時標記）：沿 X 每 ~14 m 一段，場地外的不登記。
    - 一片牆是整段長的三角形，所以登記時用 `world/prop-split.js` 的 `tessellate` 把三角形細分到邊長 7 m，才切得出缺口。
    - 打穿一段時：
      - `World.damBreach` 把沒打穿的部分重新做成碰撞方塊（每個連續的區間一個）。
      - 切掉那一段的三角形（深度方向放寬 12 m，包含扶壁與上下游面）。
      - 缺口底部留下低的瓦礫（`lowWreck`：高度 ≤ 跨越的高度 × 0.9）。
      - 放在那一段上面的物件摔壞。
      - 上游的水面高於缺口底部時，從缺口往下游噴出水流 40 秒（`addFlow`，`team` 'all'＝所有人都受傷，`game/support.js` 的 `updateFlows` 為此擴充）。
  - **隧道口**（`buildCorridor` 記在 `world.tunnels`）：
    - 細分到 6 m，外框的下面 30 m 當命中形狀。
    - 打壞時焦黑、坍方的岩塊（`shatterProp` 以岩石演出），入口前留下低的岩塊（不擋武裝列車）。
  - **平台外緣**（洋上都市的護欄、高空軌道的平台側板，主題建模時記在 `world.rimMeshes`）：
    - 每個街區的四邊每 ~30 m 一段；洋上都市整條的護欄方塊在登記時細分（`BoxGeometry` 依長度分段）。

- **Grid 086 的甲板格子**：`regDecks` 處理 `seg` 'grid' 的甲板。
  - 格子本身直接打得壞（不是 `noDie`，血量 12,000），打壞時整格掉下去（`propDamage` 對結構本體改走 `propCollapse`）。
  - 四角的支柱和旁邊的格子共用（`p.ofs`），撐著的格子都倒了才拿掉支柱。
  - 承重柱全壞的判斷改成逐一檢查 `ofs` 裡的每個結構。
- **岩頂**（技研都市、坑道網）：不登記成物件，以免拖慢投射物的判定。
  - 投射物飛到岩頂的最低點以上時（拋物線的砲彈不算）呼叫 `roofDamage`，依格子記血量（`ROOF_HP` 9,000，依岩石的屬性倍率）。

    - 拿掉岩頂平面那一格的三角形（格子＝平面的一格）。
    - 落石、加色的光柱照到地上、地上留下低的岩塊。
    - 之後子彈從洞穿過去。
  - 霧沒有改：渲染風格每格依基準值重設霧。
  - 同步：房主送 `roofx { k }`；血量表多一種項目 `['r', 格子]`。
- **只受損的範圍**（`segProtected`，`SEG_SAFE` 25 m）：在範圍內時血量最少留 1，不會被打穿。
  - 範圍包含：

    - 出口、補給台、資料終端：`campRing` 記在 `world.protect`。

### 設定「地圖物件的破壞」（2026-11-03）

使用者試玩後覺得很難打碎，定案分成三段。

| 設定 | 內容 |
|---|---|
| 易破壞 `easy` | 對地圖物件的傷害 ×4，材質倍率最低 0.8；高 4 m 以下的都踩得平；承重的壞一半就倒 |
| 可破壞 `normal`（預設） | 維持原本的手感 |
| 不可破壞 `off` | 和改版前一樣：只有改版前就打得壞的物件可以打壞，沒有受損階段與殘骸；不踩平、不倒塌、岩頂不擋子彈也不開洞 |

- 所有模式的材質倍率最低都是 0.6：混凝土與岩石的能量倍率改成 0.6、岩石的實彈倍率改成 0.6。
- **實作**：
  - 設定存在 `ctrl.destruct`，設定畫面的 `#ctrlDestruct`。
  - `Game.destructMode()`：客機用房主送來的設定（快照 `mis.dm` → `destructNet`）。
  - 倍率在房主的 `propDamage` 套用：不改物件的血量，所以客機看到的血量與階段和房主一致。
  - 「不可破壞」的判斷：
    - `World.regProp` 記 `p.legacy`：`regRest`～`regSegs` 期間（`regNew`）登記的是改版後的物件。
    - `propLive` 決定打不打得壞。
    - `destructibles()` 不列出打不壞的物件，所以子彈照舊被它們的碰撞擋下。
  - 推土要塞與廢鐵合成體照常作用在打得壞的物件上。廢鐵合成體另外排除結構本體、承重柱、局部打穿的段：它們不會因為傷害而損毀，會被一直吸附。
  - 自訂關卡的物件同樣套用倍率。
  - `NET_VERSION` 11.20。
