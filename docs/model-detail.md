# 程式模型精細化（載具、地圖物件、小物件）

2026-10-29 定案。目標：遊戲裡的程式模型（載具、地圖物件、小物件）精細度超過 polyfork.dev 的模型（低多邊形、平面著色、小物件 350～700 三角形、HD 版 3～5 千），**載具優先**。

## 定案

- **美術方向**：依照現有風格（平面著色、`mechMats` 的磨損貼圖與面板法線、渲染風格的著色器與描邊照舊），只提高造型與細節。
- **效能**：內顯電腦要跑得順。面數可以提高，以分級（近處完整、遠處拿掉小細節）與合併控制繪製次數；每期跑 `scripts/model-bench.js` 比較。
- **全部維持程式模型**（不用外部 GLB；伺服器預設組與本地模型庫照舊可以換 GLB）。
- **車輛的動作**：車輪依速度轉、懸吊依地形起伏、履帶捲動、旋翼的轉動圓盤、砲管後座。
- **損壞外觀**：依 AP 冒煙、火花、掉板、凹陷、爆胎（和專屬敵人的 `rig.dmg` 同一套）。
- 不停下來等確認，一期接一期做完（每期測試、提交、推送）。

## 品質標準（每件都要達到）

- 三層細節：輪廓／中層（面板、框架、門、窗）／小細節（螺栓、纜線、把手、標示）。
- 沒有裸露的基本形體：方塊一律倒角，看得到的圓柱至少 12～16 段，輪胎、槽體用剖面旋轉。
- 每件至少三種色調；頂點色烘焙的遮蔽（零件之間的縫、貼地處）、凸邊的磨損、由地面往上的髒污。
- 面數預算（完整版）：小物件 800～2,500、一般地圖物件 2～8 千、地標 1.5～4 萬、一般載具 6 千～1.5 萬、Boss 載具 2～5 萬三角形；
  遠處的版本（拿掉小細節）大約一半。
- 碰撞、命中、外框（`PK` 的 `ob`／`bounds`）與原本相同，只改外觀；關卡生成的亂數呼叫順序不變。

## 技術

### 共用工具（`render/detail.js`）

- 幾何：倒角方塊、圓角圓柱（倒角的頂底）、剖面旋轉（`lathe`）、截面擠出（`extrude`，H 型鋼、護欄、門框）、沿折線掃出的管線與纜線（`sweep`，下垂的纜線 `sag`）、輪胎（胎紋、胎肩）、輪框與輪轂（螺帽）、履帶零件（驅動輪、惰輪、負重輪、托帶輪、履帶片）、旋翼葉片（扭轉）、雜訊岩石（細分球＋fBm＋壓扁＋層理）。
- 頂點色烘焙 `bakeTint(geo, opts)`：遮蔽（零件外框之間的距離、貼地）、凸邊磨損、髒污漸層；材質加 `vertexColors`。
- 小細節分級：小零件（螺栓、把手、天線…）放進另一個網格（`userData.fine`），`lodTick` 依鏡頭距離隱藏。

### 載具

- 車輪：剖面旋轉的輪胎（胎紋）、輪框、輪轂、擋泥板、懸吊；依速度轉動（`m.wheels`）、依地形起伏（`m.susp`）。
- 履帶：驅動輪、惰輪、負重輪、托帶輪、履帶片（貼圖捲動 `m.treads`）、側裙。
- 車體：面板分割線、焊縫、鉚釘、艙蓋、潛望鏡、拖鉤、工具箱、車燈（發光）、後照鏡、格柵、排氣管。
- 飛行器：旋翼輪轂與扭轉的葉片、轉速高時換成半透明的轉動圓盤（`m.rotorDisc`）、進氣口、排氣口、起落架、感測器球、武器掛架。
- 塗裝：陣營色、虛構的部隊編號與標誌（`DECAL`）、泥漿與灰塵的漸層。
- 動作只改外觀，各端自己算，不改網路協定。

## 實作說明

- **開啟方式**：`bakeAll(root, { tint, cache, fineDist, upgrade })`（`render/geometry.js`，P／CB 的模型）與
  `new PK().tint(o)`（`world/prop-models.js`，地圖物件）。沒開的模型完全照舊。
  - `tint`：`true` 或 `tintCtx` 的選項（`ao` 遮蔽強度、`wear` 凸邊變亮、`grime` 貼地髒污、`gh` 髒污的高度、`y0` 地面）。載具用
    `{ ao: 0.85, grime: 0.32, gh: 1.1 }`。
  - `cache`：快取鍵。同樣的模型第二次建造時直接用合併好的幾何（零件數量與材質出現的順序要相同；不同時自動重算）。
  - `upgrade`（預設開）：合併前把舊的基本形體換成精細的（`detail.js` 的 `upgradeGeo`：方塊最短邊 ≥ 0.12 m → 倒角方塊、
    圓柱半徑 ≥ 0.12 m → 14～24 段＋頂底倒角、球半徑 ≥ 0.15 m → 16～20 段），所以只要打開 tint，整個模型就一起變精細。
  - 材質：P 的模型直接把材質的 `vertexColors` 打開（材質是每台各一份的 `mechMats`），沒有頂點色的網格會補白色；
    PK 用 `vcMat`（打開 vertexColors 的複本，顏色與自發光共用同一個物件、透明度跟著原材質，遮擋淡出照常）。
- **小細節**：`fine(fn)`（geometry.js）／`k.fine(fn)`（PK）裡的零件另外合併成網格、不投影，`fineReg` 登記，
  `renderMain` 每格 `fineTick(鏡頭)` 依距離（預設 70 m）切換顯示。遊戲實體的模型之後會被 `mergeRig` 合併成蒙皮網格，
  小細節也一起合併（減少繪製次數比較重要），所以分級只在地圖物件上作用。
- **載具零件**（`render/vehicle-kit.js`，P 與 PK 都能用）：`vWheel`（輪胎＋輪框＋螺帽，P 時是會轉的群組）、`vTrack`（驅動輪、
  惰輪、負重輪、托帶輪、包住它們的凸包掃出的履帶＋捲動的貼圖）、`vLight`／`vLamp`／`vMirror`／`vExhaust`／`vHatch`／`vJerry`／
  `vBox`／`vAntenna`、`vRotorDisc`（旋翼的轉動圓盤）。
- **車輛的動作**：rig 的 `wheels`（`[{ o, r }]`）、`treads`（履帶的貼圖）、`susp`（車身群組）由 `animateMech` 的 `vehicleRoll`
  依車身前方的移動距離轉動、捲動、前後傾；運輸車輛（`world/map-extras.js` 的 Vehicle）由行駛速度轉動 `mesh.wheels`。
- **損壞外觀**：rig 的 `dmg`（`render/foe-damage.js`，和專屬敵人同一套）：冒煙點、AP ≤ 25% 時脫落的零件（獨立的群組），
  `dmg.unmerge／remerge` 轉給 `rig.unmerge／remerge`（`mergeRig`）。
- **地圖物件的同類材質合併**（PK.tint）：沒有貼圖、不發光、不透明度 1 的標準材質依粗糙度與金屬感分成 3×3 類，顏色烘進頂點色，
  同一類併成一個網格（`detail.js` 的 `matClass`／`classMat`；可以淡出的類別每個物件各自一份材質，遮擋淡出照常）；小細節全部併成一類。
  精細的物件三角形變多，但繪製次數和原本差不多。
- **運輸車輛**（`world/map-extras.js` 的 Vehicle）建好後以 `mergeRig` 合併（車輪是骨頭）。
- **量測工具**：`node scripts/model-bench.js`（每個模型的三角形與網格數、各地圖的繪製次數／三角形／幀時間，`--compare`）、
  `node scripts/model-shots.js 槽位…`（模型庫檢視窗的近拍，`--html` 用舊版比較）。

## 第二輪精細化（2026-11-05 使用者要求）

使用者看過地圖互動裝置的重做之後要求：「用這新的工具配合之前的工具把非機甲／載具以及地圖物件再做一次更精細的建模」。
範圍是模型庫的「非機甲／載具」（139 個）與「地圖物件」（252 個）兩個分類。

- **工具**：`render/dev-kit.js`（地圖裝置做的零件：倒角方塊 `bx`、圓柱 `cy`／`cz`／`cx`、剖面旋轉 `lathe`、兩點之間的桿 `rod`、
  折線管 `pipe`、下垂的纜線 `cable`、螺栓圈 `boltRing`、螺栓列 `boltRow`、警示斜紋 `hazard`、百葉 `vents`、散熱鰭片 `fins`、
  把手 `handle`、欄杆 `railing`、液壓缸 `piston`、控制台 `consoleAt`）改成**兩種容器都能用**：geometry.js 的群組（P 的零件清單）
  或地圖物件的 `PK`（`put` 依容器分派；小細節 `fineOf`）。主題模組由 `themes/kit.js` 轉出（`K`、`D`、`markText`）。
  另加 `prop-models.js` 的 `markText`（一排長短不一的字塊，當成標示上的字）與 `rockPile`（幾塊雜訊岩石合併成一個網格、保留頂點色）。
- **做法**：每件物件在原本的造型上再加一層小細節（包在 `k.fine` 裡，遠了隱藏），外框（`ob`／`bounds`）、碰撞、受損的脫落零件與
  亂數呼叫都不變。可以脫落的零件（`inPart`／`dmgTier`）裡的細節不分級、用零件本身的材質，否則每個零件多一個網格。
- **順帶修正**：`PK.buildTint` 把不能歸類的材質（雙面、發光、有貼圖）只用材質當合併的鍵，不同零件的同一個材質會併到第一個零件上
  （冰原的雷達天線碟面跑到底座、照明塔的燈面跟著第一盞燈）——改成每個（材質, 零件, 小細節）一組；半圓拱屋的外殼角度錯了
  （一半埋在地下、看起來只剩拱肋），改成地面以上的半圓柱。
